Architecture Specification

WebPi Autonomous Coding Agent

Zero-Dependency, In-Browser Autonomous IDE, Virtual File System, and Execution Engine

1. System Architecture Overview

WebPi executes entirely within the browser's thread without Node.js, Webpack, or external microservices. It interfaces with an OpenAI-compatible completion endpoint (LM Studio, Ollama, vLLM) over Server-Sent Events (SSE). 3. Autonomous Agent Loop (UML Sequence Diagram)

The autonomous agent loop (runAgentLoop) iterates sequentially up to a maximum limit of 25 turns. Every mutating call generates an immutable workspace snapshot before tool execution, enabling atomic rollbacks. 

sequenceDiagram
    autonumber
    actor User
    participant UI as Chat & Workspace UI
    participant Agent as Agent Execution Loop
    participant Budget as Context Token Budgeter
    participant API as LLM Endpoint (/chat/completions)
    participant Snap as Snapshot Engine
    participant VFS as Virtual File System

    User->>UI: Submit prompt / instruction
    UI->>Agent: handleSendPrompt()
    Agent->>Agent: Set running state & AbortController

    loop Until terminal response or max iterations (25)
        Agent->>Budget: buildContextMessages(systemMessage)
        Budget-->>Agent: payloadMessages (anchored start, pruned middle)

        Agent->>API: POST /chat/completions (stream=true, tools=AGENT_TOOLS)
        
        loop Stream Processing (SSE)
            API-->>Agent: data: { choices: [{ delta: { content, reasoning, tool_calls } }] }
            Agent->>Agent: Parse thinking (<think> or reasoning_content)
            Agent->>Agent: Reassemble streaming tool_calls JSON chunks
            Agent->>UI: updateStreamingDOM() (Real-time render)
        end

        alt Tool Calls Present
            loop For each Tool Call
                Agent->>Snap: captureSnapshot("Before " + tool_name)
                Snap-->>Agent: snapshotId
                Agent->>VFS: executeTool(name, parsed_args)
                VFS-->>Agent: executionResult (string)
                Agent->>UI: addChatMessage("tool", executionResult, snapshotId)
            end
            Note over Agent: Re-enters loop to provide tool output back to model
        else Terminal Text Response
            Agent->>UI: Render final assistant response
            Note over Agent: Break loop
        end
    end

    Agent->>UI: setAgentStatus(false)

4. Subsystem Breakdown

4.1. Workspace Layout & 2D Dual-Axis Resizer

The workspace divides into four responsive panes: Files (Top-Left), Chat (Bottom-Left), Code Editor (Top-Right), and Sandboxed Preview (Bottom-Right).

A central handle (#centerResizeHandle) monitors pointer movements via setPointerCapture. As users drag, percentages are calculated relative to the workspace container and written to custom CSS properties:

clampedX = Math.max(15, Math.min(85, ((e.clientX - rect.left) / rect.width) * 100))
clampedY = Math.max(15, Math.min(85, ((e.clientY - rect.top) / rect.height) * 100))

4.2. Context Window & Token Budgeting Engine

To prevent local models with small context windows from failing with HTTP 400 Context Overflow, buildContextMessages() calculates character-to-token estimates (~3.4 chars/token):

Budget = Math.max(4096, contextWindow - Math.min(maxTokens, Math.floor(contextWindow * 0.35)))

The budgeting engine keeps the System Prompt and the User's Root Objective strictly anchored. Intermediate conversation turns and raw file payloads are pruned in First-In, First-Out (FIFO) sequence when total tokens exceed the budget.

4.3. Virtual File System (VFS) & Safe Replacement

Tool Name Parameters Function & Safety Enforcement
read_file path Returns raw text from the in-memory dictionary. Returns an error if the file does not exist.
write_file path, content Creates or overwrites files and auto-registers parent directories.
edit_file path, old_str, new_str Ensures safe targeted replacements. Counts occurrences of old_str: rejects with an error if 0 matches or >1 matches occur to prevent file corruption.
delete_file path Deletes the file entry and shifts the active file pointer.
create_folder path Registers a folder in the folder Set.
delete_folder path Recursively deletes the folder and all prefixed file keys.
move_file source_path, target_path Copies file contents to the destination key and unlinks the source.

4.4. Sandboxed Preview & In-Memory Asset Inliner

The preview engine runs directly via an iframe's srcdoc property. When refreshPreview() executes, an in-memory preprocessor extracts index.html, searches for linked stylesheets and scripts, and replaces them with inline equivalents from the VFS: 

// Stylesheet inlining regex
html.replace(/<link\s+[^>]*rel=["']stylesheet["'][^>]*href=["']([^"']+)["'][^>]*>/gi, (_, href) => {
  const norm = normalizePath(href);
  return (norm in files) ? `<style data-inlined="${norm}">\n${files[norm]}\n</style>` : match;
});

4.5. Pure-JavaScript Zero-Dependency PKZIP Engine (MinimalZip)

WebPi exports workspaces directly to standard .zip archives without external libraries. The layout uses a standard PKZIP binary structure:

5. Agent State Machine (UML State Diagram)

The state machine below describes the agent lifecycle through reception, parsing, safety checkpoints, and tool execution: 

stateDiagram-v2
    [*] --> Idle

    Idle --> ContextPreparation : User submits prompt
    ContextPreparation --> StreamingResponse : Build pruned message budget & dispatch fetch

    state StreamingResponse {
        [*] --> IngestSSE
        IngestSSE --> ParseThinking : delta.reasoning / <think>
        IngestSSE --> ParseToolCalls : delta.tool_calls
        IngestSSE --> ParseContent : delta.content
        ParseThinking --> RenderDelta
        ParseToolCalls --> RenderDelta
        ParseContent --> RenderDelta
        RenderDelta --> IngestSSE : Next chunk
        RenderDelta --> CheckTermination : Stream done
    }

    StreamingResponse --> CaptureSnapshot : Tool calls detected
    StreamingResponse --> ErrorHandling : Network failure / Abort

    state ToolExecution {
        CaptureSnapshot --> ExecutingTool : Checkpoint files saved
        ExecutingTool --> FormatResult : executeTool(name, args)
        FormatResult --> CheckpointLinked : Append snapshotId to chat turn
    }

    CheckpointLinked --> ContextPreparation : Next loop iteration (loopCount < 25)
    
    StreamingResponse --> Idle : Finished natural response (No tools)
    ErrorHandling --> Idle : Report error bubble

6. Security and Isolation Model

  • Air-Gapped & Zero Dependencies: Contains zero external font, script, or stylesheet references.
  • Strict iframe Sandbox: The live preview executes with sandbox="allow-scripts allow-modals allow-forms allow-same-origin allow-popups" to prevent escape into the parent IDE window.
  • Non-Destructive Rollback: Snapshots are immutable in-memory records. If an LLM hallucinates an error or deletes code, clicking ↩ Rollback restores the exact prior state.
